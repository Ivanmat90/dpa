# Changelog

## 3.1.0 - TUI

### Новое
- `dpa tui` - необязательный интерфейс на Textual с поддержкой мыши: поиск пакетов с отметками и панелью информации, список установленных, системные действия, история, алиасы, настройки языка.
- Textual не нужен для CLI: ставится по запросу в приватный venv (`dpa tui --install-deps`, `./install-dpa.sh --with-tui`), а при его отсутствии `dpa tui` предлагает установку. Установленный в систему Textual тоже подхватывается.
- Операции, меняющие систему, идут через обычный терминал (`App.suspend()`): работают пароль sudo и подтверждения apt/dnf/pacman.
- Бэкенды умеют отдавать структурированные данные: `search_hits()`, `installed_packages()`, `info_text()`.

### Исправлено
- Установщик падал (`set -e`), если `/dev/tty` существует, но терминала нет (CI, docker, cron); теперь проверяется, что tty реально открывается.
- В выводе команд аргументы со спецсимволами выводятся в кавычках (можно копировать в shell).

## 3.0.0 - модульная версия

### Исправленные ошибки
**Язык и установщик**
- `LANG = "$LANG_CODE"` нигде не подставлялось, язык из установщика не доходил до dpa. Теперь: `DPA_LANG` -> `~/.config/dpa/config.json` -> локаль системы; смена командой `dpa lang`.
- В установщике сообщения задавались до выбора языка и были всегда английскими.
- `curl` без `-f` мог установить HTML страницы 404 как `/usr/local/bin/dpa`; комментарий «самодостаточный» не соответствовал действительности (скачивался `main` с GitHub).
- На live-ISO Arch (root, без sudo) установщик падал на `sudo -v`.
- Автодополнение bash: флаги подставляли команды, DE не подставлялись после `--de`; `.zshrc` мог подключать `compdef` до `compinit`.

**Работа с пакетами**
- `dpa remove` не учитывал алиасы; пользовательские алиасы не показывались в `alias list`, `alias add` без аргументов молча ничего не делал.
- `sudo` добавлялся по наличию слов `install`/`update` в команде, в том числе для `search install`.
- Код возврата всегда 0, даже при ошибке.
- `pacman autoremove` вызывался без целей (всегда ошибка); `-Scc --noconfirm` стирал весь кеш; `update` на Arch делал `-Syu`, а на apt/dnf разное.
- `zypper`/`yum` числились поддерживаемыми, но `autoremove` для них был неверным; убраны (бэкенды теперь плагины - см. README).
- Жёсткие `-y`/`--noconfirm` для remove/upgrade/autoremove; теперь вопросы задаёт менеджер, `-y` включается явно.
- `dpa uninstall` под обычным пользователем не мог удалить `/usr/local/bin/dpa`.
- База и конфиг под `sudo` создавались в разных домашних каталогах и с владельцем root.
- Соединения SQLite не закрывались; ненужная таблица `packages`.
- Мёртвый код: подкоманда `pacstrap`, `self.lang`.

**Arch Linux**
- `arch-server`, `arch-dev`, `arch-gaming`: в `open()` передавался текст скрипта вместо пути (падение сразу после pacstrap). То же с `00-nvidia.conf`: путь попадал внутрь файла.
- `arch-config` предлагалось запускать внутри chroot, где dpa нет. Теперь работает с live-ISO через `--target`.
- Проверка `os.path.exists('/mnt')` вместо `ismount`: установка могла уйти в ОЗУ live-системы.
- Пароль root фиксировался как `root:root` и печатался в подсказке.
- В списках пакетов по умолчанию не было `grub`/`efibootmgr` (CLI) - `grub-install` падал.
- `multilib` не включался, из-за чего ломались `lib32-*` (драйверы) и `steam`.
- `makepkg` для yay запускался от root (это запрещено); теперь от указанного пользователя (`--user`).
- `mysql`/`mongodb`/`elasticsearch`/`kibana`/`kafka` не существуют в официальных репозиториях Arch под такими именами; `exa` заменён на `eza`, `neofetch` на `fastfetch`.
- PostgreSQL/MariaDB включались без инициализации каталога данных; nginx и apache включались одновременно (конфликт порта 80).
- VirtualBox получал `xf86-video-vmware`; несколько GPU (гибридные ноутбуки) не поддерживались; i3 ставился без `xorg-server`.
- `sudoers` дописывался напрямую без проверки; теперь `sudoers.d/10-wheel` + `visudo -cf`.
- `limits.d/99-gamemode.conf` из gaming отключал realtime для всех; `$SUDO_USER` в chroot был пуст.

### Новое
- Оформление: баннер, цвета, иконки, таблицы, время выполнения, ASCII-режим для консоли без Unicode, `NO_COLOR`.
- `--dry-run`, `-y`, `--no-color` в любом месте командной строки; короткие имена команд.
- `alias remove`, `history -n`, `list <фильтр>`, `lang`, `completion`.
- Модульная структура, тесты, автодополнение из парсера.
